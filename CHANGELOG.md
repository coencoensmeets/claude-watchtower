# Changelog

What changed in the panel, newest first. Releases are the tags on this repository — `v0.1.0` and so on — which is also what the panel's own updater reads, so a heading here has a tag beside it in **Settings → Panel version**.

Entries say what changed and, where it is not obvious, why. Anything worth a paragraph gets one: the reasoning is the part that is expensive to reconstruct later.

## Unreleased

- **What you are supposed to be working on, and a session already working on it.** A **GitLab** tab beside History, and a work items icon in the app bar next to Settings. The icon opens every open item assigned to you across every GitLab this machine is logged in to — a launcher rather than a report, so the whole row is the press and it opens a terminal running `claude` in that project's folder, briefed with the item. Like every new session the panel starts, it starts in auto mode. Items are grouped by project because the project is the folder, the folder is stated in each group's header, and the groups are ordered by their most urgent item so the thing to do next is at the top; a project with no checkout here sorts last and asks where first. The rows are the ones the GitLab tab draws, rail and scoped labels and all — title, link, labels, milestone, description and the last few comments. The brief ends by asking the session to get its bearings and say what it thinks the work is, rather than by telling it to implement anything: a first prompt ending in *now do this* gets an implementation of the first paragraph before anybody has read the code. The tab is the same thing for one session's own project, and it goes two deep: a list, and one work item in full.

  The list is the project's open items behind two chips — **Yours** and **All open** — that carry their own counts and cost nothing to switch between, since the project is read once and looked at two ways. Two things are drawn as what they are rather than as labels. Priority is an order to work in, so it becomes a rail down the leading edge of the row and the sort the list is in, highest first and untriaged last. The rail is ink, heavier the more it matters, and never a colour: in this panel ember, lilac and lime are what sessions are doing and rose is something going wrong, so an urgent work item drawn red would read as a failure. A scoped label is a field and its value, so `priority::high` is drawn as two halves in the colour the project gave it, which is how GitLab draws it and what keeps six labels on a row scannable. Assignees are initials rather than avatars, because an avatar is an image on somebody else's server and a list of forty would fetch forty of them.

  Opening an item stands it in front of the list, the way a subagent's conversation stands in front of a session's: description and comments as markdown, and three things to do with it — start a briefed session on it, create the branch GitLab would have named for it, or copy its reference. Escape comes back. **New work item** is a compose card over the list rather than a dialog, offering the project's own labels drawn as they will appear once filed.

  Matching an item to a folder is the part GitLab cannot help with, so the panel keeps its own index — keyed by each checkout's remote, built from the sessions in the list and the folders it has been shown before, widened by `CLAUDE_WATCHTOWER_PROJECT_DIRS` if you set it. A project with nothing checked out here says so and offers the folder chooser instead of a button that cannot work, and the folder you pick is remembered.

  It holds no credentials. Everything goes through `glab`, which already has your tokens and already knows your hosts, so there is nothing to configure, nothing stored, and nothing that outlives the access you meant to give. **Settings → Sessions → GitLab** names the hosts it can read and, for one it cannot, the `glab auth login --hostname …` line that fixes it. Which hosts those are is decided by asking each one — a single call to `/user` — and not by `glab auth status`, which reports `! Invalid token provided` for any token whose metadata it cannot fetch, a description that fits plenty of tokens that work. Believing it locked the panel out of a GitLab that was answering perfectly well, so now only *No token provided* is taken at its word, since that is the one state with nothing to try. Filing an item and starting a session are behind the same loopback gate as sending a message, and no request here carries a host, a project or a path: it names a session, and the project is read out of that checkout's own remote.

- **Ctrl+Enter sends now**, as it does in Claude Code's terminal (Cmd+Enter on a Mac). Enter on a working session waits for the turn to end. Ctrl+Enter puts the message into the turn that is running, so you can redirect it without stopping it first. Claude Code decides how the turn makes way: it takes the message in, or ends the turn and runs the message next. This works for sessions in a terminal and for sessions the panel runs. On those, the strip of typed-ahead messages also gets a **Send now** button.
- **Comments on a passage, designed in the styleguide.** The styleguide has a new **Comments on a passage** pattern, and the panel now follows it. A comment is a draft until it is sent, and drafts are butter. A commented passage gets a butter highlighter stroke, and the stroke fills the whole line while its note is open; on your own ink messages it is a butter underline. The note is a butter-tinted card tucked under its message, with its tight corner toward it and no connector line. It leads with an ink circle, **You** and a **Draft** tag, then the quote ruled in butter. You write in the filled field with the lilac focus ring, with the Enter and Shift+Enter keys spelled out beside it. **Done** is an ink pill with its check riding in a lime circle, and edit and delete are quiet round buttons. The pill that rises over a selection is ink, with **Comment** lit in butter. **Send** floats as an ink pill with the number of drafts in a butter bubble and the arrow riding in lime. How commenting works is unchanged.
- **Artifacts show up in the Preview tab.** When a session publishes a page with Claude Code's `Artifact` tool, the panel now files it under that session's **Preview** tab on its own, with the lamp on the tab and the icon on the row, without the session also calling `show_preview`. The frame shows the local file, since claude.ai pages cannot be framed, and a **claude.ai** button opens the published copy. A republish moves it to the top. Each publish is filed once, even across restarts, and publishes older than two days are left alone so a fresh install does not fill every Preview tab with history.
- **Commands left running in the background are visible.** A session whose turn has ended reads as waiting for you, even while a build, a download or a watcher it started is still running. The panel tracked subagents but not these. It now picks up every command Claude Code put in the background, whether it was started with `run_in_background` or moved there when it ran past its two-minute timeout. The row says **1 in background**, the strip over the composer gets a **shell** chip next to any agent chips, and tapping the chip opens the command and the end of its output, which updates while it runs. The MCP `list_sessions` tool lists them as `backgroundCommands`. A command counts as running while a process still writes to its output file, so one left behind by a closed session does not show as running forever. Without `/proc` to check, the panel falls back to Claude Code's completion notice.

## 0.4.0 — 2026-11-14

- **A tmux session's permission mode is current, and can be changed from the panel** ([#5](https://github.com/coencoensmeets/claude-watchtower/issues/5)). Claude Code writes the mode into the transcript only now and then, never when it changes, so a session sitting at its prompt kept showing whatever mode it last wrote down, which could be Manual for a session in Auto. For a session running in tmux the panel now reads the mode off the footer under its prompt. The header gets the same mode chips a panel-run session has, and picking one presses Shift+Tab in the pane until the footer shows that mode. The MCP `set_mode` tool does the same for these sessions. Other terminals still show the transcript's reading, because a key sent to a window can land in the wrong tab.
- **A terminal session in tmux can be answered from the panel** ([#3](https://github.com/coencoensmeets/claude-watchtower/issues/3)). A session standing on a permission prompt or a question used to be answerable only at its own terminal, because its socket takes nothing but messages. A tmux pane can be reached exactly, though, so for a session running in tmux the panel now reads the prompt off the pane and shows it on the same card a panel turn's prompt gets. **Allow**, **Refuse**, **Answer** and **Skip** press the matching keys there. The screen is read again before any key is pressed, and nothing is sent if the prompt has changed. The MCP `answer_question` and `answer_permission` tools work for these sessions too. Other terminals are unchanged, because a key sent to a window can land in the wrong tab.
- **A VS Code session stopped at a permission prompt now shows as needing an answer** ([#4](https://github.com/coencoensmeets/claude-watchtower/issues/4)). The extension writes no status, and CPU and the transcript are as quiet at a prompt as at the end of a turn, so such a session used to read as finished and nothing was raised. The panel now looks at the transcript's last tool call and at the processes below the session: a call with no result and no new process is a prompt, and the row says which tool it wants to run. A call with a new process is a tool at work, so a long build in a VS Code session now reads as **Working** instead of finished. Terminal sessions are unchanged, because they report waiting themselves. The row's badge also says **permission** instead of **prompt** whenever Claude Code's session file says a permission prompt is up.
- **A new README.** The top of the README is now a showcase: an animated hero, the four states, a tour GIF of the real panel, screenshots of each tab, the phone, the MCP tools and the settings, an animated quick start and a diagram of how it works. Every picture comes in light and dark and follows GitHub's theme. The full manual follows it unchanged. The pictures are made, not drawn: `tools/readme/stage.sh` stands up a demo machine with made-up sessions in a private namespace, `capture.mjs` records it, and `art.py` draws the SVGs.
- **Live location in the house style.** The styleguide's Maps section gains a live-location and turn-by-turn pattern, built and tested in a walking-route guide. It covers a "you are here" dot with a heading wedge and an accuracy circle, a locate button that is lilac while the map follows you, the stretch to the next turn in ember with an arrowhead, a dotted line back to the route when you are off it, and a guidance banner in three tones: plain, ember for a turn close by, and lime when you arrive. The skill ships a third kit file, `watchtower-nav.js` (`WTNav`), cut from the guide like the others. It snaps a GPS fix onto a route, finds the turns and words them. SKILL.md adds the how-to and the gotchas: secure context only, the compass on iPhone, and how to test it.
- **The top of a long conversation can be reached again.** A page of history cut at the bare message count could open halfway through an answer, with tool steps and no question above them. A page now starts at the message that began the turn. And a read that stopped at the byte cap said there was nothing older, which took away the button that loads more. It now says there is more whenever the file is bigger than what was read.
- **Starred sites.** A star on the Preview tab keeps a preview under the sessions, in a **Starred sites** list at the bottom of the sidebar, openable with no chat attached. A tap opens it in a tab of its own. Right-click or hold it for **Open**, **Copy link**, **Open a chat with it** (a new session in the folder it came from, with the site already named in the message box), **Show the session it came from**, **Rename…** and **Unstar**. A starred site is a copy, kept in `~/.config/claude-watchtower/starred.json`, so it outlives the session and its previews, and a page on disk keeps the address it already had.
- **Holding a session row on a phone opens its menu again.** The rows were draggable, and a phone's browser starts its own drag on a long press of anything draggable, which cancelled the hold. Rows are now only draggable with a mouse, so on a phone, holding a row opens its menu, and rows cannot be dragged to reorder them there.
- **A session with a default name goes by what it is about.** A session still called what it was born as — the folder and a tag, like `claude-watchtower-1d` — now takes the title Claude gives the conversation once it has one, in the list and the detail header, and follows it as the title moves. A name you typed, or one the session was given with `/rename`, still wins, and clearing a name you typed goes back to the title. The line under the name is dropped when it would only repeat it.
- **More in Settings → Appearance.** The light/dark switch becomes four choices. **Theme**: Light, Dark or System; System follows the device as it changes, so a phone that goes dark at sunset takes the panel with it, and says which it is showing right now. **Text size**: Small, Default, Large or Larger, scaling every word while icons and layout stay put. **Density**: Comfortable or Compact, which shortens the session rows (smaller avatars, no subject line), tightens the conversation and trims the header and tabs. **Motion**: System, Reduced (nothing loops or flies in; colours still ease) or Off (nothing moves at all), on top of whatever the device asks for. Each is remembered per browser, so a phone and a laptop can differ. The colours themselves stay fixed, because they mean session states.
- **New sessions are pinned.** A session started from **+ New** — a folder from the list, *Another folder…*, *Describe it…*, or another session's `start_session` — is pinned from the moment it starts, so it survives a panel restart and being stopped. Unpin it from the row as before. *In a terminal instead* is not: the terminal starts that one, and the panel only meets it later.
- **A research skill.** A new **Research skill** switch in **Settings → Claude skills** installs `skills/watchtower-research`, a method Claude follows when you ask it to research something online: frame the question and its sub-questions, search from several angles at once, prefer primary sources and read the page rather than the search snippet, confirm anything important in two independent sources, and report the answer first with a link per claim, how sure it is, and what it could not check. It also treats web pages as data rather than instructions and keeps your private details out of search queries.

- **+ New → Describe it…** With **Watchtower tools** switched on, the + New menu opens with a box where you say what you want to do, and Claude works out where it belongs. It looks through the projects on this computer — folders sessions have run in, the ones on the list, and git checkouts in your home — and answers either *open in ~/robot-app* or *new project ~/coffee-roastery-landing*, with a sentence on why and, for something new, how it would set it up. Nothing happens until you press **Start**, and the answer can be sent elsewhere first: another known project, or any folder from the browser. Start makes the new project's folder if there is one, starts a session the panel runs there, names it, pins it so it survives a restart, and sends your words as its first turn — for a new project, after asking it to set the project up (git, README, scaffolding). The deciding is a quick headless Claude with no tools, like the commit-message button, and whatever it answers is checked: only folders inside your home, a new folder only under one that exists, a name that is already taken becomes that folder.
- **The panel follows the styleguide's new component recipes.** Text fields are filled pills with a lilac ring on focus; switches are lime with an ink knob when on, in both themes; the snackbar is an ink pill; notices in Settings are alerts on a tint with a round icon (rose for a dead end); the context menu and dialogs take the guide's radii and the ink scrim; the Details facts are a key–value list without rules; the context and usage meters have hatched tracks; counts are badges; Usage figures are KPI tiles; and the empty states carry the hatched circle that means "nothing here yet".
- **The styleguide covers far more.** `docs/design/styleguide.html` gains six sections. **Forms**: filled-pill fields, search with a trailing action, select, textarea, error state, checkbox, radio, switch, slider, stepper and drop zone. **Feedback**: alerts, toast, badges, status dots, progress bars and rings, spinner, steps, skeletons, empty state and tooltips. **Navigation**: side nav, breadcrumbs, pagination, accordion, menu with shortcuts, avatar stack and dialog. **Tables and lists**: a sortable table, key–value list, activity timeline and date-range calendar. **Charts**: a data palette of its own (eight categorical hues validated for colour-blind separation in light and dark, a sequential lilac ramp, a diverging violet–orange scale, status colours), KPI tiles with sparklines, line, area, column, stacked, ranked-bar, scatter and heatmap charts with hover tooltips and a table view, segmented bars and meter lists, and the rules (no pies, one y-axis, thin marks). **Maps**: a quiet basemap palette, pins, price chips, state dots, clusters, you-are-here, routes with casing, areas, choropleth regions, popups, floating controls, a legend, a phone bottom sheet, and how to style Leaflet and MapLibre to match. The charts are drawn by a small dependency-free helper, `WTViz`. The house-style skill now ships all of it: `tools/style_kit.py` cuts `watchtower.css` and `watchtower-viz.js` out of the guide, and a test fails if they fall behind. The guide's theme toggle also survives the Preview tab's sandbox now.
- **An About tab in Settings.** What the panel is, the version it is on, links to the source, the issue tracker, a star and a coffee, the disclaimer that it is not an official Anthropic product, and the licence.
- **A house style for everything Claude makes.** A new **Watchtower house style** switch in **Settings → Claude skills** installs a skill that makes the Watchtower styleguide the default look for any page, site, report, dashboard or UI a session builds, unless you ask for a different style; an existing site that already has a design of its own keeps it. The skill ships `watchtower.css` — the guide's tokens, type, buttons, chips, cards, stat tiles and meters, lifted from `docs/design/styleguide.html` — and the rules for using them, including a light/dark toggle that survives the Preview tab's sandbox.
- **Previews: open what a session made.** A session that builds something you can look at — a styleguide, a report, a static site, a dev server — hands it to the panel with the new `show_preview` MCP tool, and it appears in a **Preview** tab on that session, with a lamp on the tab and an icon on the session's row until you have looked. The tab shows it in a frame on a dotted board that you can size to a desktop (with a browser bar), a tablet or a phone (with a bezel), reload, copy the link of, or **Open** in a tab of its own. On a phone, swipe up on the preview (or tap it) and it grows to fill the whole screen with the page live; the cross, Escape or the phone's back button put it back. Several previews sit in a row of chips above it, newest first, and showing a page again moves it to the top and reloads it. The frame is kept through the pane's repaints, so a working session does not reload the page under you. Pages on disk are served by the panel from their own folder at `/preview/<token>/…`, sandboxed so a page cannot act as the panel; a dev server on `localhost` is opened on the panel's host name from a phone. A new **Preview skill** in **Settings → Claude skills** tells Claude to do this whenever it makes something viewable. See *Previews* in the README.
- **Settings → Claude skills.** A new tab of recommended add-ons for Claude Code, each behind a switch: turning one on installs it for every session on this computer, and turning it off removes it. Three to start with: **Watchtower tools** (the MCP server below, registered with `claude mcp add --scope user`), **Let Claude approve other sessions' tools** (the same server with approvals allowed, a separate switch because it is a separate decision), and the **Watchtower skill**, linked into `~/.claude/skills/`, which tells Claude when the tools are worth using. The switches read what is really installed from Claude Code's own files, so a server removed by hand shows as off, and anything called `watchtower` that is not this panel's is left alone. Only this computer can flip them.
- **Claude can drive the panel.** The panel is now also an MCP server — turn on **Watchtower tools** in **Settings → Claude skills**, or `claude mcp add --scope user watchtower -- python3 /path/to/claude-watchtower/mcp_server.py` by hand — and a session can list every session on the machine, read what one has been saying, send it a message, start a new one, stop a turn, answer its question, switch its mode, rename, focus or end it. It starts nothing of its own: each tool is a request to the panel already running, on loopback, so it can do what the panel can and no more. A message sent this way is labelled in the conversation with the sending session's name, and a session cannot send to, answer for or end itself. Allowing another session's tool use is off unless `CLAUDE_WATCHTOWER_MCP_APPROVALS=1` is set, because a session that can approve another's prompts can run anything through it; denying is always allowed. See *Letting Claude drive the panel* in the README.
- **A new look: Watchtower.** The panel is restyled to a design of its own, written down in `docs/design/styleguide.html`. Colour now means state and nothing else: ember for a session that needs an answer, lilac for one that is working, lime for one waiting on you, and hatching for one that is closed. Whatever you can press is ink in light mode and chalk in dark. The type is Urbanist, a geometric face with round bowls to match the shapes, with Roboto behind it for anything it has no letter for. Controls are pills and circles, and containers round off more the bigger they are. Rows are stadiums with the state-coloured avatar in their left end; the detail pane is one large surface lifted off the page, with the selected session's state as a colour block at its top and the fold handle in a circle cut from its corner; the tabs are a segmented pill. **The base colour and contrast settings are gone**, and *Reset colours* with them: the palette is fixed because its colours are the states, and a generated scheme could make two states look alike. An old saved setting is still read and simply ignored.
- **The panel moves.** Three kinds of motion, kept apart, all in `web/styles/motion.css`. When you do something: presses give a little and spring back, a row leans toward the pointer and its avatar grows, and the tab pill slides to the tab you chose. When something new turns up: the panes rise in once when the page opens and the rows cascade down the list, a new message rises in from its own side, a row that changes state pops its avatar with a ring of the new colour, and the header's new colour grows out of its corner over the old one. While a session works or waits: an arc circles a working avatar and a slow sheen crosses its header, and a session that needs an answer nudges its icon every few seconds. The list and the pane are rebuilt from markup on every poll, so `web/src/ui/motion.ts` remembers what was on screen and marks only what is really new: a poll that changed nothing moves nothing, older history loading above does not animate, and a session you come back to after a while raises only its last few messages. With reduced motion switched on in the system, all of it holds still.
- **Notifications on a phone.** Allowing notifications on the phone did nothing: Chrome on Android refuses to show one a page makes itself (`new Notification()` throws) and will only show one through a service worker. The panel now registers a small one, `/sw.js`, and shows every notification through it, the desktop's included. It caches nothing and answers no requests. Tapping a notification brings the panel forward on that session, or opens the panel on it if none was open. It needs a secure context, as notifications always have: localhost on the computer, the `https://` tailnet address on the phone. They still come from the open panel, so a phone that has put the browser to sleep hears nothing until it is opened again. **Settings → Notifications** now always says where things stand: once they are allowed, which used to leave the section blank, it says so and offers **Send a test notification**, which reports why it did not show if it does not; and on plain http, where a browser gives a page no notifications whatever it reports, it says to open the `https://` address instead.
- **A new session can start in any folder from a phone.** *Another folder…* opened the desktop's folder chooser, a window on the computer's screen that nobody holding the phone could see. Away from the computer — or on a desktop with no chooser — it now opens a folder browser in the panel itself: this computer's folders, starting beside where your sessions are, with *Up one folder*, *Show hidden folders* and *Start here*. It lists and starts in folders inside your home folder only, behind the same key and gate as starting a session. At the computer it still opens the desktop's chooser.
- **Settings has tabs.** Appearance, Notifications, Sessions, Phone and Panel each have a tab of their own instead of being stacked into one long page, where the phone code had become a long scroll away. The tab you were on is remembered while the browser tab is open, so coming back to Settings lands where you left it, and the strip takes the arrow keys, Home and End like any tablist. *Reset colours* moved into Appearance, which is what it resets.
- **The panel from anywhere, over Tailscale.** A phone could only open the panel on the same wifi. **Settings → Phone** now opens with a **From anywhere** part that arranges Tailscale, above the wifi address — it is the one that works wherever the phone is: the install line when it is missing, then a **Reach from anywhere** switch that runs `tailscale up` (opening the sign-in page the first time) and `tailscale down`, and — once the laptop is on the tailnet — its tailnet address with the key, as text and as a code. Startup prints it too. The phone arrives from its own tailnet address, so the key is asked for as on the wifi; the panel deliberately does not use `tailscale serve` or `funnel`, which would proxy every request in from loopback, where no key is asked. The switch answers only this computer: from a phone it could strand the phone, or hand out a link that puts the laptop on someone else's tailnet.
- **https over Tailscale, on the same port.** The panel fetches a certificate for this machine's tailnet name with `tailscale cert`, renews it twice a day, and serves it itself: the first byte of each connection is peeked, and only a TLS handshake (`0x16`) is wrapped, so the wifi address goes on working over http and bookmarks keep their port. It is the phone's own address that arrives — no proxy on loopback — so the key is asked for as before. The **Phone** tab switches the code to the `https://` name when the certificate is in, and otherwise says why not, linking to the admin page where HTTPS Certificates are switched on. Over https the phone gets the microphone, notifications and the modern clipboard.
- **Talk instead of typing.** A microphone button on the message box, beside the picture buttons, uses the browser's own speech recognition: the words land in the box as you say them, as if typed, and Send is still yours to press. It asks for the microphone the ordinary way before it listens — on Android, speech recognition alone could refuse without ever raising the prompt — and a refusal says where the fix is: the site, Chrome's own app permission, a browser that will not do speech recognition, or a microphone another app is holding. Pressing it again, sending, or a phone's own silence timeout stops it; while it listens it is drawn in the error colours with a slow pulse, because "this is recording you" is not a state to miss. Nothing is installed — Chrome, Edge, Safari and Chrome on Android have it, Firefox does not, and Chrome transcribes on Google's servers. Browsers only lend a page the microphone in a secure context, so the button is only drawn where that holds: at once on the laptop (localhost), and on the phone over https, below.
- **A new session starts in Auto.** One started from the panel — run here, or opened in a terminal — began in Manual, asking about things its own terminal would have started out allowing. Both now start in Auto, Claude Code's own default; the mode can still be changed from the header before or after the first message, and a session adopted or resumed keeps whatever it was in. Worth knowing what Auto is: a classifier decides what needs asking about, and what it allows never reaches the panel.
- **Pasted pictures stay out of git, and are gone after five days.** A picture pasted into the box — or a file dropped with no path of its own — is written into the session's folder under `.claude/`, because that is the only place a session can read without a permission prompt nobody is there to answer (a session asked to read one under `~/.cache` was denied). In any repository but this one it then showed up in `git status`, waiting to be committed. Each of those folders now carries a `.gitignore` of its own saying `*`, so git never sees it and nobody's own `.gitignore` is touched. They were kept a fortnight and swept only when the same project was pasted into again; now it is five days, and the panel sweeps every folder it has written into at startup and every six hours, removing the ones it empties. This repository also stops tracking the one test picture that was committed before it ignored the folder.
- **No more Remote Control button in the header.** It handed a session to a terminal with `--remote-control` on, back when that was the only way to reach a session from a phone. The panel now reaches the phone itself — on the wifi, and from anywhere over Tailscale — so a second button beside *Open in terminal* was one more thing to read for something rarely wanted. Remote Control is still there for anyone who wants it: **Open in terminal**, then type `/remote-control` at that prompt, and typing `/remote-control` into the box of a session the panel runs now says exactly that.
- **Scrollbars that belong to the panel.** Every scrolling box — the changelog, the conversation, the lists — had the platform's own scrollbar, which on Windows is a grey gutter with arrow buttons in a palette nothing else on the page uses. They are now a thin rounded thumb in the scheme's own colour on no track at all, darker under the pointer, and they follow the theme into dark mode. Firefox, which cannot round a scrollbar, gets the thin, tinted version.
- **Node installed into the checkout's virtualenv is found.** `pip install nodejs-wheel-binaries` — what the panel itself suggests when there is no Node — puts the binary inside the package, under `site-packages/nodejs_wheel/`, not in the venv's `bin/`. The build only found it when the panel ran on the venv's own Python, so a plain `python3 server.py` fell through to whatever `node` was on the PATH, which may be too old to build with. The venv is now looked in on disk, so it is found whichever Python starts the panel.
- **A phone can open a panel running in WSL.** In mirrored networking the code points at the right address and the phone was still told the site cannot be reached: Windows' Hyper-V firewall for WSL blocks incoming connections by default, and WSL only ships rules for ICMP and mDNS, so the connection was dropped before Linux saw it. The panel now asks Windows whether its port is let in. When it is not, it says so on startup and in **Settings → Phone**, with an **Allow on Windows** button that adds the rule behind a UAC prompt on the desktop, and the one-line `New-NetFirewallHyperVRule` command to paste into an administrator PowerShell instead. In NAT mode the address on the code is one only the computer can reach, and the panel says to switch to mirrored rather than pretending otherwise. Asking Windows takes about two seconds, so the answer is handed back from the last check at once and renewed in the background — the phone's address and code no longer wait for it.
- **The message box has room on a phone.** The two picture buttons, Send and Stop shared one row with the box, and on a phone they took more than half of it — the box was a sliver a few words wide. Below 600px the box now has the whole width and the buttons sit in a row under it: the pictures at the start, Send and Stop at the end, where the thumb is.
- **Choosing a folder works when the panel runs in WSL.** The chooser was a Linux one — zenity, kdialog, or Tk — and under WSL that is a window drawn through WSLg, which opens behind the browser if it opens at all and can only see the Linux side. Under WSL the panel now asks Windows for its own folder dialog through `powershell.exe`, starting in the Linux folder (as `\\wsl.localhost\…`) and taking either side back: a folder under `C:\` arrives as `/mnt/c/…`. It is found the same way when the panel runs as a systemd service, which has neither `WSL_DISTRO_NAME` nor `/mnt/c` on its PATH.
- **A picture can be added without the clipboard.** An image button beside the box opens the platform's own file chooser, and on a phone a camera button beside it opens the camera. A phone's photo — a HEIC, or a 48-megapixel JPEG past the size the server takes — is redrawn as a JPEG no longer than 2560 pixels on its long side before it is saved; a picture that is already fine goes as it is.

## 0.3.0 — 2026-09-02

- **Settings says when *Open in terminal* cannot work, before you go looking for the button.** Two things have to be on the machine — one of the terminals the panel knows how to open, and `claude` on the PATH the panel would open it with — and until now the only place either was reported was a tooltip on a disabled button, on a row you had to open first. **Session actions** now carries the answer for the whole panel: silent when it can, and when it cannot, which of the two is missing and what to do about it. Where there is no terminal at all it offers the line that installs one, guessed from the package manager it can find and drawn the way the phone address is — the command itself with a copy on the end of it, because a button reading *Copy the install command* hides the one thing worth reading. A `CLAUDE_WATCHTOWER_TERMINAL` pointing at a terminal that is not there is told apart from a machine with no terminal, and offered no package to install: that machine may well have one already, and the thing to fix is the variable.

- **Remote Control, on the one transport that can have it.** `/remote-control` typed at a session the panel runs is answered by Claude Code with *not available in this environment*, and no plumbing on this side changes that: Remote Control needs an interactive session, and a session the panel runs is `claude --print` down a pipe, which is the opposite of one. So the panel offers what it can actually do — a **Remote Control** button beside *Open in terminal* that hands the session to a terminal running `claude --resume <id> --remote-control <name>`, named after the row you have been reading it under. Its own button rather than a tick on the neighbouring one, because registering a session with your Anthropic account is a different thing to have decided than opening a window, and not one to inherit from the last time you pressed the button next to it. Offered and refused on exactly the same terms as the plain hand-back — it is the same hand-back — and typing `/remote-control` into the box now says where the button is instead of reporting that this session does not list the command.
- **Open in terminal stops telling you to wait for a turn that will not finish.** A session parked on a permission ask is mid-turn — the turn really is in flight — so the hand-back was refused with *let that finish first*, on a turn whose only ending is the answer being asked for. The refusal stands, because letting go of the pipe abandons a prompt nobody else can answer; the sentence now names the two ways out instead: answer it, or stop the turn. The button and the server's own 409 say the same words.
- **A session says how many subagents it is running**, and a `Task` row in the conversation opens what that agent did — its own conversation, tools and changes included, drawn the way the session's is. A session that has fanned out six agents used to read as one session doing one thing, and everything those agents did was missing from between the row that sent them and the answer that came back.
- **A subagent's conversation is drawn as somebody else's.** It reads in the panel's second colour, on a deeper surface, behind a rail: the errand it was sent on is the headline, what was said *to* it is a briefing rather than a bubble in your own colour, and while it is still working the transcript says so at the foot rather than ending mid-thought. Two conversations that look alike are two conversations you will confuse.
- **The agents a session has out are named over the box you type in**, one chip each, and a chip opens what that agent is doing. A running subagent is the one thing a working session is doing that the conversation cannot show you: the row that started it is however far back you have scrolled.
- **A session's spend now includes its subagents.** Each one keeps its own transcript, so the bill was counting only what the session itself said — on a fanned-out session that is a fraction of what was actually paid for.
- **And the pane follows a cleared session rather than dropping you elsewhere.** Clearing gives a session a new id, so the row you were reading disappears and the panel used to fall back to whatever was at the top of the list. The feed now carries where it went, and the selection follows.
- **`/clear` typed into the box works too, and does not strand the panel.** Following a cleared session to its new id was conditional on the panel's own button having asked for it, which left the command you can type doing half the job: the conversation cleared and the row went on showing a transcript that had stopped growing. The reader now follows the session whenever the id on its pipe changes, however it changed.
- **Clear works, on the transport where it can.** A **Clear** button beside *Compact* for a session the panel runs: `/clear` down the held pipe, which expands it, where a session's messaging socket queues it with expansion off and turns it into prose. The catch is that Claude Code does not empty a conversation in place — it starts a new one under a new session id — so the panel follows the session there: the held process, the queue, the mode, the row, and the name you gave it all move together, and the old transcript stays on disk. For a session in a terminal `/clear` is still the terminal's own, and the panel still says so rather than sending something that does nothing.

- **The address on the phone page carries its own copy button.** A copy icon on the right-hand end of the address, in the box the address already sits in, instead of a *Copy the address* button underneath saying what it would copy. It ticks when it has, the way the copy on a code block does.

- **Pictures in a message are shown.** A screenshot, a plot, a picture pasted into the box: named as markdown, as an `<img>` tag, or as the `[Pasted image: …]` line the composer writes, it is drawn in the conversation instead of described in it. The panel serves the file itself, and only if it exists, is a picture, and sits inside your home folder, the session's own, or the system temp folder. A remote image is still not fetched, and a tag is rebuilt from its `src` rather than passed through.
- **Maths in a message is drawn as maths.** TeX between dollar signs — inline or as a display — is rendered to MathML, which the browser draws itself: fractions, matrices, scripts, stretching delimiters, accents, the greek alphabet, `\text`, `\mathbb`, `\underbrace`, sums with their limits. The converter is written for this panel rather than pulled in: KaTeX is 280KB of script and a megabyte of fonts against a panel whose whole assets folder is 156KB, and nothing here should need installing. What it cannot read it hands back as the TeX that was written.
- **An update channel, so unreleased features can be tried.** **Panel version** in Settings now picks between **Releases** — the tags, which is the default and what everybody else is running — and **Development**, which follows the tip of the `develop` branch: written and merged, not released yet. The rules do not change with the channel: nothing moves over uncommitted work, nothing takes the browser's word for the target, and the checkout lands detached on the commit it was offered. The choice is remembered outside the checkout, because an update replaces the checkout.
- **Open in terminal works again.** It read the flag for *the panel is holding this session* as if it meant *a turn is running*, and the button is only drawn for sessions the panel holds — so it was disabled for the whole of a session's life, explaining itself by asking you to wait for a turn that had usually finished minutes ago. It now asks the same question the server does, and says how many typed-ahead messages the hand-back would take with it.

## 0.2.1 — 2026-08-27

- **A click on an icon does what the icon says.** Every icon-only control in the panel — the copy button on a code block, the ⋯ on a turn, the buttons in the app bar — is a button with an `<svg>` filling its face, and the delegated hit test insisted the thing clicked was an HTML element. An `<svg>` is not one. So the ring of button around the glyph answered and the middle did not, which reads as a button that works if you hit it just right and is dead if you aim at it. The copy button was the worst of them, being almost entirely glyph.
- **Copying is synchronous now**, inside the click that asked for it, rather than after an `await` that some browsers treat as the end of the gesture — and when the clipboard cannot be reached at all, the text is selected instead so Ctrl+C finishes the job, rather than a snackbar reporting failure and leaving you to find it again.

## 0.2.0 — 2026-08-27

- **A path written in a conversation is a link.** Click one and it opens: a file goes to the editor at the line the message quoted it at, a folder goes to whatever the desktop opens folders with. The tool lines above a turn are clickable too, so the file an `Edit` touched is one click away. What counts as a path is deliberately narrow — rooted, or a folder and a suffix, or a bare name inside code marks with a known extension — because a false positive turns prose into a live control.

## 0.1.0 — 2026-08-25

The first tagged release, and the one that made the updater useful: with no tags in the repository it had nothing to compare against and said so.

### The panel

- **An index and a detail pane**, in Material 3's list-detail shape. Every session on the machine, one row each, sorted so anything waiting on you is at the top — or dragged into an order of your own, which then survives sessions going busy and idle again.
- **State that is inferred rather than believed.** Claude Code writes a status only when it changes, so an old `busy` proves nothing. The panel asks for a second opinion — CPU over five seconds, and whether the transcript is still growing — before it overrules a reading, and holds a session's liveness across the quiet gaps inside a turn.
- **The conversation**, read from the transcript on disk: messages, tool calls, and the patch a change carries — folded to a few lines, or opened full-width as a side-by-side comparison.
- **Git and History** for the repository a session works in, including staging, committing and the diff of a single file.
- **Usage and cost**, totalled from the transcript at Anthropic's published per-token prices, and how much of the subscription has gone in the app bar.

### Talking to a session

- **A composer** that sends over the session's own messaging socket, with the three limits it has stated plainly rather than hidden.
- **Pictures pasted** into the box and **files dropped** on it are saved and sent as paths, because every transport a session has takes a string.
- **Turns run by the panel itself**, for a session whose terminal has closed — the permission mode picked per turn, and the prompts it raises answered from here.
- **Commenting on a passage**: select it and the remark goes back attributed, as a quote the session can find in its own transcript.
- **The question a blocked session is standing at**, drawn as a card so you can read it without going to find the terminal.

### On a phone

- **Served to the local network by default**, guarded by a key that nothing off this machine is answered without. `--local` keeps it to this machine.
- **A port of its own**, picked once for the install and kept, so the address is the same tomorrow and two panels on one network do not collide.
- **A code to scan** in Settings, so the address and its key need not be typed.
- **The panel itself works on a phone**: the actions on a turn reachable without a right-click, press-and-hold on the list, and the shell measured against the visible glass rather than the glass plus a toolbar.

### Taking things out

- **A message downloads as markdown** from a right-click or the button on the turn — the markdown that was written, not the HTML it was drawn as.

### Updating itself

- **The panel updates from these tags.** It reads them out of its own checkout, offers only what it does not already have, and refuses to move over uncommitted work or off a branch of your own.
